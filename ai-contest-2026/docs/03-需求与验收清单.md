## B. 演示案例——不能再删掉的场景

- [ ] ✅ **沈阳文旅 Skills 的形成与科技馆复用**：前端、后端、底层框架规则以及生成规范，展示规则如何约束实际代码。
- [ ] ✅ **福州科技馆商城**：熟悉业务的后端与 AI 先产出可体验版本、产品反馈迭代；API/H5 调试页面与接口文档传给前端，说明沟通减少的机制。
- [ ] 🟡 **科技馆产品人员自主 AI 开发**：产品基于高保真 HTML 原型在独立开发环境、独立分支上推进部分功能；QA/上线范围不夸大。
- [ ] ❌ **SRS/WebRTC 音视频复杂联调**：症状/日志 → AI 假设 → SSH/MCP/浏览器/服务配置核对 → 人工排除/确认 → 结果；要明确至少一个真实可核证的链路。
- [ ] ❌ **AI+MCP 跨系统排障**：数据库/SSH/浏览器，多服务之间链路检查；不能只讲工具名。
- [ ] 🟡 **权限/绕过校验纠偏**：AI 提议绕过校验，人拒绝，改查真实依赖/配置问题，展示安全架构判断。
- [ ] 🟡 **订单/出票恢复与数据库异常**：先固定批次、口径、状态后判断是否补偿，避免“一次 SQL 看似正确”的误判。
- [ ] 🟡 **多实例结算/库存台账对账**：状态口径和时点统一，适合备份页或真实场景备用。
- [ ] ✅ **项目一键初始化**：docs / Skills / MCP / AGENTS.md / 变更记录 / 迭代看板 / 测试 / 部署记录；已实现与规划整合清晰分层。
- [ ] ✅ **Super App 多 Agent 协作**：Lead、角色模板、任务卡状态、会话 ID/Owner、交接/缺陷回派、协作的上下文连续性。
- [ ] ✅ **Super App 研发前置设计分析**：从高保真原型生成技术架构、UI/UX/UE 规范、组件/样式/交互约束，再派发给开发。
- [ ] ✅ **后期升级产品验收 Agent**：新增独立验收节点、原型截图和实现截图比较、读取原型源码、拒签/重开并退回原开发、复验、角色提示词规则升级，强调提高 AI 交付质量。
- [ ] 🟡 **真实截屏证据**：原型、实际页面、偏差报告、任务卡、会话ID、测试/验收日志、角色卡前后变化；缺失时用“示意图”标明，不冒充实测。
- [ ] ⬜ 每个主案例有 3～5 个可验证点：问题—AI做法—人判断—修订—证据/结果。

## C. 现场演示与竞赛评分

- [ ] ⬜ 15 分钟内穿插实际演示和讲解，预留计时；不能做成 15 分钟纯 PPT。
- [ ] ⬜ 至少展示**3 个不同 AI 研发环节**的真实协作记录（例：需求/原型与规范、代码实现、跨系统调试或测试/验收）。
- [ ] ✅ Super App 页中直接切换真实工程，演示一项小且未实现的功能，示例“任务卡会话 ID 一键复制”需先确认未实现。
- [ ] ⬜ 现场展示真实提示词、AI 输出、代码 diff、可见运行或测试结果、人的取舍；不能预录视频替代，也不能模拟“测试通过”。
- [ ] ⬜ 项目初始化只需真实展示已有工程规范和流程，不必花时间现场重建整套工程。
- [ ] ⬜ SRS 故障用于真实复杂排障证据展示；不建议现场接入未脱敏生产环境以防泄露或因网络失败。
- [ ] ⬜ 演示失败也如实记录原因与处理，不能伪造通过。
- [ ] ⬜ 所有案例材料经过公司/客户敏感信息脱敏，避免生产 IP、日志 ID、用户数据、密钥、商用代码外传。

## D. 数据与表达质量

- [ ] ✅ 禁止“几百倍、1000%”等未经验证的浮夸提效数字；只留少量方向明确的保守指标。
- [ ] 🟡 Skill、MCP、任务卡等数量需要注明统计范围、时间、去重口径、来源和是否原创/安装。
- [ ] 🟡 2026-11-20 Super App 任务快照 67 任务、55 done、12 blocked、263 日志：**done != 独立验收交付**。
- [ ] 🟡 传统方式与 AI 方式的开发、沟通、交接时间对比若缺历史基线，表述“待核数据”或“典型场景估算”。
- [ ] ⬜ 质量收益主要用“原型差异被发现并回派、规则升级”证据链，不声称 100% 原型一致。
- [ ] ⬜ 不把拥有 17 个 MCP 配置名说成开发了 17 个原创 MCP；第三方 Skills 不计独立研发。
- [ ] ⬜ 区分“代码存在”“文档声称”“真实运行验证”“公司推广实证”“下一步规划”。

- [ ] ✅ 交付格式是**单文件离线 HTML**，而非 PPTX。
- [ ] ⬜ 页面支持浏览器翻页/全屏/前后导航/页码/讲稿提示；能键盘操作。
- [ ] ⬜ 视觉是成熟、清爽的蓝青科技感，而非夸张营销风；优先内容可读、讲述节奏。
- [ ] ⬜ **流程升级动效**：先完整的原始开发→测试→完成，再出现“测试通过但与原型不一致”，最后插入“产品验收 Agent”、展开原型源码+截图对比+证据链+退回复验。
- [ ] ⬜ 注意“回派机制原本已有”，**不要**动效中表现为产品验收 Agent 加入前连通用 Bug 回派和会话追溯都不存在。
- [ ] ⬜ 页面上明确 Super App 独立实践已形成；融入科技馆一键初始化仍是未来计划。
- [ ] ⬜ 不把产品人员真实岗位和“产品 Agent”同名混淆。
